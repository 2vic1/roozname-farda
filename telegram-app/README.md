## چرا این معماری؟
مطابق مستندات رسمی `core.telegram.org/bots/serverless`:
- بک‌اند = ماژول‌های JavaScript ساده داخل `tgcloud/` (بدون npm، اجرا در V8 isolate روی سرورهای تلگرام)
- دیتابیس = SQLite داخلی پلتفرم (`sdk/db`) — از Prisma استفاده نمیشود
- فرانت‌اند Mini App = بیلد استاتیک (Vite) که در `app<app_id>.tgcloud.ai` میزبانی میشود
- Endpoints فقط از داخل Mini App با initData تأییدشده صدا زده میشوند — بدون نیاز به لاگین

## محدودیت‌های شناخته‌شده (صادقانه)
- **Cron ندارد** (در مستندات فعلی زمان‌بند وجود ندارد) → بروزرسانی خودکار فقط وقتی اپ باز است
  یا با دستور `/check` در چت. هشدارِ خودکار در غیاب کاربر فعلاً ممکن نیست.
- **npm ندارد** در بک‌اند → موتورها به JS ساده پورت شده‌اند؛ ستاره‌شناسی در فاز ۲ سمت فرانت اجرا میشود.
- **z-ai-web-dev-sdk آنجا اجرا نمیشود** → گزارش هوش مصنوعی با کلید API خود کاربر (سازگار OpenAI)
  که با `/setkey` در چت ذخیره میشود (هیچ کلیدی در کد هارد نمیشود).

## مراحل دیپلوی (وقتی کاربر آماده بود)
1. در @BotFather → بات → **Serverless** → روشن کن → **CLI Access → Access token** را بردار
2. `npm install` در همین پوشه
3. `npx tgcloud login` (توکن را میپرسد) → `npx tgcloud push` → `npx tgcloud migrate`
4. در BotFather، دکمه Menu Button را روی اپ ست کن (بعد از فاز ۲ که فرانت آماده است)
5. در چت بات: `/setkey sk-...` (کلید هوش مصنوعی) — سپس `/check` برای تست
